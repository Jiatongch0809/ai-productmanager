# 单品拆解优秀案例学习规范

来源：团队沉淀的单品拆解案例库。

## 正式产物必须回答

1. 它是什么，服务谁，在什么场景解决什么问题；
2. 它为什么比传统方案更有价值；
3. 它如何形成“输入/感知 → 识别/理解 → 判断 → 反馈/行动 → 平台/服务”的闭环；
4. 哪些机制、场景、能力和商业模式可以迁移；
5. 机会是否值得进入机会池；
6. 最大风险、最大未知和下一步验证是什么。

## 默认6页结构

1. 产品总览与核心判断；
2. 用户与产品魅力：传统方案、痛点、购买驱动、Magic Moment；
3. 技术与实现机制：输入→感知→理解→判断→反馈/行动→数据闭环；
4. 机制拆解与迁移边界；
5. 机会提炼与风险；
6. 综合判断与验证任务。

资料充分时可扩展至8–10页，但不得为了填页数增加空泛内容。

## 视觉质量规则

- 标题优先写判断句或价值转变句；
- 每页设置一个信息锚点；
- 生图用于整页构图、产品主视觉、机制图和场景表达；真实数字、来源、证据等级和关键文字用可编辑覆盖层承载；
- 保持主视觉、机制/价值卡、来源/行动三个层级；
- 深色科技底或高留白浅色底由产品类型和确认的视觉系统决定；
- 页脚保留页码、章节、来源和数据口径。

## 质量门禁

- 事实、宣传、推断、未知分开；
- 机制必须形成闭环；
- 机会必须明确机制、场景、用户/付费者、新问题、新增能力和迁移边界；
- 同时呈现正向信号和反向风险；
- 结论强度不能超过证据强度；
- 结论页必须有1–3个可执行验证任务。
