# 产品情报拆解 Skill：事实底稿与原生可编辑产物

## 核心规则
标准路径为：

```text
逐页内容脚本/报告大纲 → 事实与来源核验 → Markdown 主稿 → DOCX/PPTX/XLSX 原生产物 → 文件校验
```

产品拆解默认不调用 `image`/生图接口，不生成逐页整页 PNG，也不把图片拼接成 PPT。只有用户明确要《产品机会一页卡》时，才按总控规则单独调用一次生图生成单张视觉卡。

## 内容前置门禁
每页或每个报告章节进入排版前必须完成：
- 判断句标题；
- 核心结论；
- 4–7 个实质信息模块（必要时增加页数）；
- 机制链、对比、机会、风险或结论的具体内容；
- 事实状态、来源、时间和口径；
- 产品视觉锚点可使用用户提供的原图、官方公开素材或文字/图表表达，不额外生图；
- 完整文字稿、字段和版式规则。

## 产物适配
- 默认交付：Markdown 主稿。
- 用户要正式报告：生成 DOCX，保留标题层级、表格、来源和结论。
- 用户要汇报：生成原生可编辑 PPTX，使用 SVG/形状/文本/图表/用户提供的产品图片；不调用生图。
- 用户要证据或竞品台账：生成 XLSX，记录来源、日期、证据等级、事实/判断/未知和核验状态。
- 用户要产品机会一页卡：先生成可编辑 Markdown/DOCX 底稿；经明确需要视觉卡时，才生成单张 PNG，并核对图片与底稿一致。

## 信息密度标准
优秀样板基准为每个案例 6–8 页，资料复杂时扩展到 10–12 页。每页形成完整信息页，而不是单一产品海报。分析页必须保留产品实物、产品形态、使用场景或机制局部中的至少一个锚点；优先使用事实表、流程图、对比图和原生图表。

## 质量检查
逐页检查：标题是否形成判断；事实和来源是否完整；机制/对比/机会/结论是否清晰；中文是否可读；图表是否可编辑；产品锚点是否存在；PPT 是否为原生内容而非整页图片；Word/XLSX 是否可打开、非空且与底稿一致。任何一项不合格则重排版或重写，不得通过再次生图规避。
